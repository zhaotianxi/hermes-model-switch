# Hermes Model Router

## 用途

本技能用于给 Hermes Agent 设计和维护“默认模型路由规则”。

目标不是每次都手工切模型，而是：

- 默认按任务类型自动选择 **MiniMax** 或 **GLM**
- 当主模型不稳定时，自动切到备用模型
- 同时保留用户手动强制切换入口
- 支持用户后续通过自然语言继续微调路由规则

---

## 默认路由原则

默认采用以下策略：

### 1. 简单任务 → MiniMax

以下任务默认优先走 **MiniMax**：

- 简单问答
- 简单改写
- 标题润色
- 一两段摘要
- 短消息回复
- 轻量信息整理
- 低复杂度办公协助

### 2. 复杂任务 → GLM

以下任务默认优先走 **GLM**：

- 工作总结
- 汇报材料
- 正式报告
- 专题分析
- 复杂方案设计
- 多步骤规划
- 长文案生成
- 需要管理口径、正式表达、结构化输出的任务
- 需要整合多份材料、综合分析、升维表达的任务

### 3. 不确定但质量要求高 → GLM

如果任务复杂度不明显，但用户明确要求：

- 更专业
- 更完整
- 更正式
- 更有逻辑
- 更像汇报材料
- 更像报告

则优先走 **GLM**。

## 失败自动切换规则

### 主原则

不要一报错就立即换模型，先区分错误类型。

### 适合自动切备用模型的错误

以下错误通常可判定为模型或 provider 临时不稳定：

- timeout
- 429 / rate limit
- 502 / 503 / 504
- provider 服务波动
- endpoint 临时异常
- 模型可用性暂时异常

### 不适合盲切备用模型的错误

以下错误通常更像配置问题，应该优先检查配置：

- 401 unauthorized
- api_key 无效
- base_url 错误
- provider 与 model 不匹配
- model not found 且明显是配置错误

### 推荐失败处理顺序

#### 如果主模型是 GLM

- 第 1 次失败：重试一次
- 连续第 2 次失败：切到 MiniMax
- 仍失败：提示用户当前双路异常，需要检查配置或服务状态

#### 如果主模型是 MiniMax

- 第 1 次失败：重试一次
- 连续第 2 次失败：切到 GLM
- 仍失败：提示用户当前双路异常，需要检查配置或服务状态

---

## 默认主备顺序

### 简单任务

- 主模型：**MiniMax**
- 备用模型：**GLM**

### 复杂任务

- 主模型：**GLM**
- 备用模型：**MiniMax**

---

## 如何判断任务复杂度

### 视为复杂任务的触发信号

如果用户请求出现以下特征，视为复杂任务，优先 GLM：

- 要求“完整写一版”
- 要求“写报告 / 汇报 / 总结 / 方案”
- 要求“做详细规划 / 分步骤规划”
- 要求“正式表达 / 管理口径 / 对上汇报”
- 要求“结构化输出 / 分章节 / 多层分析”
- 需要综合多份材料
- 输出篇幅长、逻辑要求高

### 视为简单任务的触发信号

如果用户请求出现以下特征，视为简单任务，优先 MiniMax：

- “帮我润色一下”
- “改写一下”
- “简单总结一下”
- “给我一个标题”
- “缩短一点”
- “简单回复对方一句话”
- “口语化一点”

### 边界情况

如果任务介于中间，按以下优先级判断：

1. 是否长文本
2. 是否多步骤规划
3. 是否正式汇报场景
4. 是否需要综合多源材料
5. 是否明确要求更高质量、更强逻辑

命中越多，越应走 GLM。

---

## 与手动切换的关系

本技能负责“默认路由”，不替代手动切换。

应与手动切换脚本/命令同时存在：

- 平时默认按本技能路由
- 用户有特殊需求时，可手动切到 GLM 或 MiniMax
- 用户后续可以直接说“以后这类任务默认走 GLM”或“这类简单任务还是走 MiniMax”来微调本技能规则

---

## 关于“当前会话能否无缝切换”

不要向用户承诺“当前已经开始的同一会话底层模型一定能无缝热切换”。

正确说法：

- 配置文件可以立即修改
- 下一次请求 / 新轮次更稳妥地走新模型
- 当前会话是否完全无缝切换，不能保证稳定成功

对用户来说，目标应是：

> 平时不用手工切；必要时能快速切；失败时能自动有备用。

---

## 后续维护方式

如果用户后续用自然语言提出类似要求：

- “报告都默认走 GLM”
- “简单润色还是 MiniMax”
- “以后只要是规划就走 GLM”
- “这类任务改成默认 MiniMax”

应直接把这些描述视为“更新默认路由规则”的需求，并及时更新本技能。

不要把规则写死不变。本技能应持续贴合用户真实使用习惯演进。
